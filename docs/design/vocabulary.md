# Vocabulary

This is a living language contract for player-facing terminology.

## Voice

Use contemporary, grounded criminal language.

Prefer short, direct wording that sounds like people managing real work rather than a fantasy class system or faux-noir narrator.

## Avoid by default

- faux-noir phrases,
- theatrical gangster slang,
- RPG labels such as ability, quest, class, mana, buff/debuff when a grounded system term exists,
- police/procedural language when the player-facing concept is not actually a police/procedural concept,
- lore paragraphs that repeat visible state.

## Information-writing rule

Interface copy should add information that numbers, layout, hierarchy, and state do not already communicate.

Bad pattern:

> This opportunity is located in another district and therefore requires the player to travel before beginning the operation.

Better pattern:

> Worth a ride if you want the take.

## Canonical-term process

When a system gains accepted player-facing terminology:
1. add the term here,
2. note rejected aliases when useful,
3. use one canonical term across code-facing presentation IDs where practical,
4. do not silently rename established terms during unrelated engineering work.

No detailed gameplay vocabulary is invented in Infrastructure 1. Terms enter this file when the relevant system is designed.
